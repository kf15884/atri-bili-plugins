# Beta 升级、验收与回退

可选测试版本，不替换GitHub原稳定版v0.7.2或默认分支。先在非生产环境验证，保存自己的配置与数据，不公开备份。

## 服务器终端

解压后进入 `atri-bili-api-0.7.5-beta.1`，执行：

```bash
sha256sum -c SHA256SUMS
bash scripts/install-upgrade.sh /请填写Koishi项目目录 请填写服务名.service
```

请替换项目目录和服务名；脚本要求root权限、Node20+与已有Koishi工程。脚本在本机私有备份配置、依赖与data后离线安装；不重写koishi.yml，也不覆盖已有运行数据。安装过程失败时会尝试恢复依赖和清单。

## QQ本人私聊验收

1. `/bili status` 确认主插件beta版本与HDS接入正常。
2. 不启用第二台时分享真实BV，确认开场、资料读取、延迟感想与追问提前发送。
3. 开启第二台前自行填写地址、Token与模型线路；建议眼镜超时300秒。使用有说话声的视频测试，检查状态显示实际成功线路与声音状态。
4. 验证失败时如实说明、不换视频、不重复回卡或重放未确认消息。

## 手动回退

停止自己的服务，选择本机 `.atri-bili-backups` 内本次升级前的正确备份恢复依赖及package.json/package-lock.json，再启动服务。不要将备份发到公开仓库；不要盲目覆盖数据库或删除state文件。也可以自行下载GitHub原稳定版按其说明安装。
