# 升级与验收

升级主0.7.2 + 眼镜0.5.2，保留原实例。根README给出唯一安装步骤。私有备份含配置、会话、data与依赖，不公开；源码目录755/文件644，私有文件600，不用chmod777。不要删除.atri-bili-packages/api-0.7.2；回退代码与依赖，不粗暴回滚数据库。

## 验收

1. /bili status显示0.7.2、HDS已连接；眼镜0.5.2，autoReadShared/watchPacing开启。本人与机器人QQ配置沿用。
2. 分别发BV、正式链接和QQ JSON卡片：先收到HDS原人设的准备观看回应，此时不评价视频；确认后开始读，模型生成预回复时不提前发。
3. 初次可把waitMinSec/waitMaxSec设为10/20以便验收，之后自行调整，默认30/90。倒计时从预回复生成完成后开始，status显示阶段/剩余等待。
4. 预回复已生成时问“看完了吗”：只发这份HDS感想，不重复卡片。预回复未生成时连续追问：没有额外“等一下”回复，完成后立即发一次。没追问则倒计时后发。
5. 分开“视频链接”和“这个你看看”两条消息：关联同一任务，不另开多轮。无关聊天仍正常处理。识别边界与超时见README。
6. 同视频重复合并；新视频替换取消旧任务；/bili pause、取消、关闭眼镜、重启都不重放草稿。未知投递不重发。
7. 读不到资料如实；没字幕不假称看过画面或音频；失败时不自动改选。HDS模型无法生成则记录失败，不套固定人设句子。
8. /bili pick和HDS主动选片仍按原卡片+对话方式；真人在QQ客户端验证卡片展示、点击和原生分段。

生产安装、真实B站/模型/QQ验收未在本轮执行。服务启动不等于整条链路已通过，登录也不等于字幕可用。不要粘贴真实Cookie/Key。
