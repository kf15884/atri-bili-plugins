# 升级与验收

升级主0.7.2 + 眼镜0.5.2，保留原实例。根README给出唯一安装步骤。私有备份含配置、会话、data与依赖，不公开；源码目录755/文件644，私有文件600，不用chmod777。不要删除.atri-bili-packages/api-0.7.2；回退代码与依赖，不粗暴回滚数据库。

## 验收

1. /bili status显示主插件0.7.8、HDS已连接；眼镜0.5.3，autoReadShared/watchPacing开启。本人与机器人QQ配置沿用。
2. 分别发BV、正式链接和QQ JSON卡片：先收到HDS原人设的准备观看回应，此时不评价视频；确认后开始读，模型生成预回复时不提前发。
3. 初次可把waitMinSec/waitMaxSec设为10/20以便验收，之后自行调整，默认30/90。倒计时从预回复生成完成后开始，status显示阶段/剩余等待。
4. 预回复已生成时问“看完了吗”：只发这份HDS感想，不重复卡片。预回复未生成时连续追问：没有额外“等一下”回复，完成后立即发一次。没追问则倒计时后发。
5. 分开“视频链接”和“这个你看看”两条消息：关联同一任务，不另开多轮。无关聊天仍正常处理。识别边界与超时见README。
6. 同视频重复合并；新视频替换取消旧任务；/bili pause、取消、关闭眼镜、重启都不重放草稿。未知投递不重发。
7. 读不到资料如实；没字幕不假称看过画面或音频；失败时不自动改选。HDS模型无法生成则记录失败，不套固定人设句子。
8. /bili pick和HDS主动选片仍按原卡片+对话方式；真人在QQ客户端验证卡片展示、点击和原生分段。

9. 看视频（可选，需第二台0.2.0）：/bili status显示“声音开启；线路：line1(画面+声音，经代理)可用 → line2(画面)可用”。分享有人说话的视频，Atri能提到听到的内容；/bili status上次成功应为“含声音”。抽帧（旧说明）：第二台装好atri-senses后，填framesToken并开启framesEnabled；/bili status应显示“第二台抽帧：在线”。分享一个视频，第二台 journalctl -u atri-senses 可见任务；Atri的感想能提到具体画面但不说听到了声音。关掉第二台再分享，应只用文字资料正常回复。

10. 开场随机化（0.7.6/0.5.3）：连续分享约10个不同视频（不要说“你看看”）——大约七成先收到一句回应、三成没回应但30–90秒后直接收到感想（感想自然带出“刚看完”）；不会连续3次都不回，也不会连续5次都先回。开场说法彼此不同（字数、语气、反问/条件/调侃都有），偶尔对卡片标题随口反应，偶尔只发一个表情包。发视频时附“你看看”：必定先回。验收时可临时把ackProbability调为0或1分别检查两条路径。

11. 消息处理（0.7.7）：①说“发个猫猫视频”，回复不应明显变慢；网络慢时这一轮可能只自然回应，几分钟内再要一次应直接带卡片。②自动选片：/bili status可看到“候选池：读取中/已就绪”，下一次生活推进才可能分享。③观看任务等待期间连续聊天，感想不应丢失，在聊天回复之后发出。

12. 连贯性（0.7.8）：①说“发个猫猫视频”，若只回了一句，接着说“挑好了吗”或“你再试试能不能发给我卡片”——应按同一请求处理（有候选就带卡片），不再出现“看这个”但没有卡片。②候选慢时只回一句后什么都别发，约2分钟内可能补发一张卡片+话（也可能HDS选择不发）；期间你发任何消息则不补发。③Atri发出卡片后，/bili status显示“观看任务（自己分享后去看）”，约30–120秒后收到她看完的补充感想（能提到画面/声音）；问“看了没”会提前发。④/bili status首行显示主插件0.7.8，并有“候选池：…”行。⑤每次要视频后 `journalctl -u hds-interlude.service --since -10min | grep atri-bilibili` 应看到“要视频：搜索词…候选N个”“要视频回合：…回复含视频链接/无视频链接；登记卡片N”，发卡时还有“匹配到待转卡片的气泡”“QQ卡片已获回执”。

生产安装、真实B站/模型/QQ验收未在本轮执行。服务启动不等于整条链路已通过，登录也不等于字幕可用。不要粘贴真实Cookie/Key。
