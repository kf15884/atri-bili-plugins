# 更新记录

## 0.7.8（眼镜仍0.5.3）
- 要视频追问窗口：要视频后10分钟内，短追问（再发一次/一个、发给我卡片、挑好了吗/没、视频呢、发了吗、发过来、好了没等，≤24字）按同一请求、同一关键词处理，消费候选池。
- 无视频守卫：本轮没有读到可发视频、而对方在聊视频/卡片/链接时，提示HDS不要说“看这个/发你了”、不假装发出、不放URL。
- 延迟补发：要视频这一轮候选仍在读取时，读好后（askDeferSec，默认120秒；0关闭）若本人没有再发消息、没有本人分享的观看任务进行中，等HDS前台回合结束后把这次作为刚才请求的延续交给HDS；HDS可以不发（mode=none即放弃）；发则走卡片→原分段，按用户请求延续投递。新的要视频/追问替换，其他新消息取消。HDS回合开始前读好的候选直接用于本轮。
- /bili status：版本号读package.json；始终显示“候选池：空/读取中/已就绪”；显示待补发；去掉写死的眼镜版本文字。
- 自己分享后观看：Atri发出的卡片取得回执后（要视频、补发、/bili pick、自动选片），开启“自己分享后去看”任务：第二台画面+声音（不受framesScope限制），失败用候选资料；HDS生成补充感想（不重复分享时的话、不再发卡片/URL、只依据真实资料）；随机等待selfWatchWaitMinSec–selfWatchWaitMaxSec（默认30–120秒），“看了没/怎么样”提前发；沿用观看任务的让位、退避、取消与重启不重放。不打断本人分享的观看任务；新的分享替换它。selfWatchEnabled默认开启。
- 诊断修复（据服务器诊断：要视频请求均已识别、候选也读到过，但HDS从未写出视频链接，卡片因此从未触发）：
  - 你明确要视频且手上有候选时，提示改为“默认挑一个发出去”（可嘴硬但边说边发），说“发你了/看这个”就必须带URL；不再写“不必每次都发”。
  - 每轮把插件真实卡片记录告诉HDS：最近24小时没有卡片真正发出时，明确之前说过的“发了/看这个”都没发成，避免她以为“刚才那张卡片”已经发过。
  - HDS同一回合重写（结构恢复/时间越界/网页观察）时保留本轮候选，最终稿仍可转卡片。
  - 搜索词去掉“看/刷/在看/看的”等，“你最近看的视频”不再去搜“看”。
  - 新增日志（atri-bilibili）：候选搜索返回/未看过条数、单个读取失败原因、要视频回合候选数/第几稿/回复是否含链接/登记卡片数、气泡匹配、卡片回执或失败、补发结果。

## 0.7.7（眼镜仍0.5.3）
- 消息处理优化（按项目“插件消息处理优化指南”，不改HDS核心）。
- 要视频：候选读取最多等askWaitSec（默认4秒）；超时这一轮先由HDS按人设自然回应、不放链接、不承诺稍后自动发，读取在后台继续，读好的候选进入候选池，下次要视频直接用。
- 自动选片：生活推进回合不再等B站网络；到间隔时只启动后台读取，下一次生活推进再把读好的候选交HDS筛选。候选池保留candidatePoolMinutes（默认60分钟），一次性使用；读取失败记2分钟。/bili status显示候选池状态。
- 观看任务：生成感想草稿前先让位给HDS正在处理的回合（最多等60秒，之后照常生成）；投递前忙碌改为0.5→4秒逐步退避并保留草稿，最长10分钟才记hds-foreground-busy（原为30秒即放弃）。
- 开场去重：不再为“和以前太像”多调用一次主模型重写；太像直接转为不回分支（连续计数随之修正）；明确“你看看”时保留这句回应。
- 未改：开场回执后才读取、30–90秒节奏、单任务、取消/暂停/重启不重放、未知投递不重发、/bili pick仍现场读取。

## 0.7.6 / 眼镜0.5.3
- 观看开场按概率：默认70%先回一句、30%已读不回直接读取；明确“你看看/帮我看看”必定先回；防连续（不回≤2次、先回≤4次）。
- 不回分支：HDS本轮回复mode=none、记录分享消息，约1.5秒后开始读取；草稿提示“没先回话、看完第一次回”；读取失败3–10秒内如实说明；草稿生成失败重试一次。
- 开场多样化：随机说法方向与长度、按当下状态；最近8条开场写入watch-state（ackHistory），相似则重写一次，仍相似转为不回分支。
- 可对QQ卡片标题随口反应（眼镜从卡片detail_1.desc/news.title提取，仅标题）；先回分支约10%只发一个HDS本地表情包，以sendSticker成功回执确认后才读取。
- “等会看/弄完再看”类开场：等待区间放宽（下限×2、上限×3，封顶600秒）。
- 未改：投递确认、重启不重放、追问合并、主动联系门控、看听资料链路。
