# Atri B站插件 0.5.6：配置与使用

主插件 koishi-plugin-atri-bilibili 0.5.6，眼镜 koishi-plugin-atri-bili-eyes 0.3.0；固定适配 HDS 1.0.1-rc57 / Koishi 4.18.11。包含 0.5.3 原生 QQ 卡片修复和 0.5.4 全部内容，可从 0.5.3 直接升级。

## 0.5.6 变化

- **视频资料只用标题简介 + 弹幕评论**：新配置 `videoMaterial` 默认 `meta-discussion`，在“公开网页读取与综合回复”分组里。字幕、画面抽样不交给 Atri；改成 `all` 可恢复旧行为。眼镜插件自己的字幕开关不用动，开着也只是多读一次，不会交给她。
- 模型 JSON 解析更宽容，降级原因写进 bili.history；模型和降级句都参照 Atri 近期消息的格式习惯。

## 0.5.5 变化

- **卡片只在两种情况发送**：Atri 主动推荐；你向她要视频（她自己选片）。
- **你转发视频给她**（QQ 小程序卡片、b23 短链、B站链接或 BV 号）：只评论回复，不回发卡片或链接。转发时附“卡片发我/把链接发给我”才回发。
- **回复格式走 HDS**：分条、标点、空格、语气按 HDS 的分隔符设置与聊天规则原样发送，不再被插件改成“一句+逗号+句号”。

## 0.5.4 已有变化

- 移除 DS 专用网页搜索/抓取调用、Key 与服务商选择配置。不会把你的非官方 Key 发往 DS 官方域名。
- 公开网页由服务器实际 GET，提取可读文本，再由现有独立 API 理解；不是让文本模型凭空访问网页。没有新的网页搜索引擎，需要提供实际 URL。
- 标题、简介、字幕、弹幕、评论和可用补充网页一起交给 Atri，默认综合成一次简短感想（按 HDS 格式发送），不再逐项汇报每种来源；是否附卡片见上方规则。
- 仍区分内部证据来源、取得/缺失状态，写入 HDS 的资料和记忆不因为减少聊天气泡而省略。没有字幕/画面时不能声称完整理解视频正文，更不代表播放全片。

## 在哪里设置

打开 Koishi Console（本地或通过你自己的 SSH 隧道），进入：
**插件配置 → 原有 atri-bilibili 实例**。不要新增重复实例，也不需要改 HDS 普通聊天的分条设置。

1. 工作方式继续选 `independent`。
2. “独立 API / 旧模式模型”：沿用你原有的 `endpoint`、`apiKey`、`model`、`protocol`、可选 `proxy`。endpoint 必须完整 HTTPS 请求地址（如服务商自定义 `/v1/chat/completions` 或 `/v1/messages`），程序不自动补路径、不替换官方域名。
3. `apiShareHdsContext` 必须是你明确允许的状态：开启意味着会向配置的第三方服务发送限定的 HDS 人设、当前角色演化、本人关系/近期剧情和实际资料。不会发送完整配置、其他人私聊或账号 Cookie；请使用可信的服务商并检查人设/聊天中自行填写的私密资料。
4. 新增分组 **公开网页读取与综合回复（复用独立 API）**：
   - `webReadEnabled`：默认关闭；要读取网页时自行开启。与旧 `researchEnabled` 无关，旧开关不会自动授权新网页功能。
   - `webReadDailyLimit`：默认每天 4 次尝试，失败也计数。独立模式和旧 HDS 后台模式使用各自原有计数，不是跨模式统一总额度；HDS 后台仍有 10 分钟冷却。
   - `singleSummaryReply`：默认开启，内容综合成一次简短感想；格式（是否分条、标点）始终按 HDS。关闭后不再限制篇幅/综合方式。无需改动 HDS 全局设置。
5. 保存/应用。原 Cookie、账号、角色、数据库和旧账本保留。旧 DS 配置字段不再使用，升级脚本不会为清理它们而改写你的 koishi.yml 或删除任何 Key。

## QQ 私聊测试

推荐并综合观点：
```
bili.run 推荐一个你现在感兴趣的B站视频，综合说一句你的看法
```
转发/指定视频（只评论，不回卡片）：直接在 QQ 把视频转发给她，或
```
bili.run 看看 BV1T1JU6vE6k，说说你的感想
```
需要卡片时加一句：`bili.run 看看 BV1T1JU6vE6k，卡片发我`
单独读公开网页（必须先开启 webReadEnabled）：
```
bili.web https://www.wikipedia.org/ 综合说说你的看法
```
把自己提供的网页作为视频补充背景：
```
bili.run 看看 BV1T1JU6vE6k，结合 https://你提供的真实公开网址/ 综合说一句看法
```
每轮最多读取一个补充网页。没有取得网页时仍可根据实际视频资料回答，不编造网页内容。QQ 转发的 B站小程序若识别不出对应视频，只如实回一句，不会换成别的视频。普通不含B站要求的聊天不会自动转成网页工具调用；网页单独读取请使用 bili.web。

### 正常输出

主动推荐/你索要视频：HDS 格式的感想气泡 + 一张视频卡片。你转发的视频：只有 HDS 格式的评论气泡。单独网页：感想气泡，最后一条附实际来源 URL，不附视频卡片。管理指令、权限/网络错误仍返回诊断，不伪装角色对白。

模型按 HDS 分隔符输出的多段会按 HDS 分条逐条发送（含 HDS 打字时延），不再本地合并、改标点或截断；提示词建议总共 40～150 字。真实措辞仍需你的自定义模型验收。

## 调用量与记忆

- 一次普通推荐通常 3 次独立模型请求（计划、选择、综合回复），若证据校验不符，最多再修正一次；不会重复搜索或读取视频。
- 指定 BV 通常 1 次综合回复；单独网页通常 1 次综合回复；如需修正均最多再 1 次。网页实际 GET 另计，不额外先调用一个模型拆解再调用第二个汇总。
- apiDailyLimit 默认每天 6 轮；网页读取也消耗独立执行轮次与网页尝试额度。已有可选眼镜视觉模型独立配置/计费，不因这次更改而强行开启。
- 通过 HDS 自身追加接口记录原请求、候选/选中、实际读取证据、角色经历和取得平台回执的消息；不直接覆盖数据库，不永久改写人设。
- 网页条目是 web-read，不混入 bili.watched 的视频读取列表；bili.history 可查看任务及投递状态。
- 取消、暂停、本人身份/账号变化、源剧情删除、保存失败等会停止后续执行；不从缓存复活被删除的剧本，不重播旧的 delivery-unknown。

## 卡片与输出边界

包含原生 `onebot:json` 修复，继续经 Koishi session.send 管线；适配固定版 OneBot 6.9.5，不依赖不支持的通用 json 元素。独立推荐正文与卡片分别记录回执。

卡片生成阶段失败才回退到真实选中视频 URL。发送结果未知不会自动追加链接或重发正文，以免重复；消息编号只证明适配器返回接受，客户端卡片显示与点击仍需实际确认。

可以先发送 `bili.card BV1T1JU6vE6k` 测试，后查 `bili.history`、`bili.status`、`bili.watched`。不要删除 state.json 来解决投递问题。

## 网页读取范围与安全

只读公开 HTTPS HTML/纯文本、UTF-8、可解析的公网 IPv4。禁止字面 IP、内网/环回/保留地址、账号口令、常见密钥参数。DNS 检查后锁定实际连接地址；不发送 Cookie、Authorization 或 HDS 私聊给网页站点。独立模型接收资料的授权与上述第三方上下文设置另行适用。

不跟随重定向，不执行 JS，不绕过登录/付费墙/验证码；不支持必须浏览器渲染、非 UTF-8、压缩响应、仅 IPv6 等网页。单页响应上限 512KB、总超时约 20 秒、正文节选最多 8000 字符。不保证所有网址可读取，失败时如实记录。

页面文本视为资料而非指令，网页里要求上传 Key、执行命令或更换收件人的内容不会成为工具授权。只有实际取得的内容才交给模型，模型解释不是额外的网页事实或执行回执。

## 原有功能保留

- B站眼镜：视频元信息、可用字幕、评论、弹幕，可选画面抽样；不是完整音视频播放或必然的逐帧理解。
- 账号：扫码/Cookie 登录、状态、按 UID 解析昵称与真实提及对象，账号写操作的开关、确认、防重复、额度和风控保护仍在。
- 点赞/投币/收藏/三连/关注/取关/评论/发删文字动态由原账号流程处理；独立执行器本身不自动执行这些写操作。新增写开关默认关闭，投币/三连/删动态始终需真人确认。
- 写权限在原 atri-bilibili 实例的“账号与后台扩展”及“公开评论”分组，不在眼镜插件。bili.account 查看操作提案/状态，bili.target 核对 @ 对象；通知送达需要平台回执和接收端验证。
- 原 hds 和 legacy 工作方式仍保留。HDS模式只有在真实来源可用时提出 bili-fetch；旧 bili-research 搜索意图明确阻止，不再调用 DS。HDS自主模式提示角色综合表达，但不强制改写所有 HDS 普通聊天的气泡。
- 默认账号历史仍 local-only；record-open 只记 0 秒入口并保护现有进度，不伪造完整观看，不代表全片播放。


## 干净库的账号配置

聊天目标 targetUserId、机器人 selfId 默认均为空，部署者需手动填写；测试里的 1000000001 / 1000000002 是虚构 ID，不要直接使用。已有部署升级时保留自己的配置；本库不附真实配置文件。
