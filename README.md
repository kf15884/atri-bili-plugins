Atri的B站子项目，与[HDS-Interlude](https://github.com/ISEKAI-MomoiCore/HDS-Interlude)配合，不是HDS官方项目。

这是可选Beta，独立beta分支和Pre-release，不替换仓库稳定main或稳定Release。基于用户交付的0.7.8诊断修复最终包/眼镜0.5.3重新脱敏打包；版本加Beta标记，不额外声称功能修复。

## 本次变化

- 候选限时读取与后台池，主叙事忙碌让位，减少重复开场模型调用。
- 十分钟内要视频短追问沿用请求；无候选时禁止假称发卡；有候选的明确请求提示HDS默认选一个，重写保留候选。
- 候选读好后的有界补发、新消息取消、真实卡片记录、状态与诊断日志。
- Atri自己发卡成功后，可通过第二台有限画面/音频理解再形成感想；不等于完整观看。
- 眼镜0.5.3的开场概率、标题反应、去重与节奏；仅将发布版本标为0.5.3-beta.1。

## 安全与数据

# Atri Bili：HDS观看节奏版

主插件 **0.7.8** + 眼镜 **0.5.3**。0.7.8要视频更连贯：同一请求的追问（“再发一次”“挑好了吗”）延续处理、候选晚到由HDS决定补发、手上没视频不再说“看这个”，Atri自己分享后也会自己看并补一段感想；0.7.7消息处理优化：要视频最多等4秒、自动选片不在HDS回合里等网络、观看任务让位HDS前台回合；0.7.6观看开场随机化：约七成先回一句（说法多变）、三成已读不回直接去看；0.7.5看视频同时听声音（默认关闭）；0.7.3新增：本人私聊向Atri要视频时，由HDS按剧本状态决定发不发；发则先发QQ视频卡片，再按HDS原节奏发她的话。本人私聊分享B站链接、BV或B站QQ JSON卡片后，先由HDS回应准备去看，再读实际资料并生成待发送感想，随机等待或在追问时提前分享。

## 功能简介

```text
明确分享一个视频 → 约70%：HDS按原人设随口回应（说法方向随机、防重复、偶尔只发表情包）
                     约30%：已读不回，直接进入读取
                        ↓ 取得真实HDS投递确认后
               眼镜读取API文字资料、可用字幕
                        ↓
               HDS生成预回复（仅内存，不提前入库/发送）
                        ↓
               随机等待30–90秒（可配置）
                ├─ 相关追问 → 提前发出预回复
                └─ 无追问 → 到时按HDS原链路发送
```

预回复未就绪时的相关追问静默合并；生成完成后立即发，不再等待。所有角色文字都由HDS生成，保持原人设、关系、记忆、分段和消息门控，不用插件独立模型/固定模板。分享视频默认只聊感想、不重复回卡。原`/bili pick`和HDS生活推进选片仍为卡片在前、原格式感想在后。

**资料读取不等于真实音视频播放。** 仅取得元信息、可用字幕与可选弹幕；开启第二台看视频后，另有几张静止画面和开头一段声音（默认10分钟）的模型理解，不假称完整看完。不执行站内评论、艾特、回复、点赞等写入，无Puppeteer依赖。

## 最新更新

**0.7.8**：①要视频后10分钟内，“再发一次/再发一个/发给我卡片/挑好了吗/视频呢/发了吗/发过来”等短追问按同一请求（同一关键词）处理，直接使用后台候选池。②本轮手上没有读到视频时，提醒HDS不要说“看这个/发你了”、不假装已发。③候选这一轮没读好：读好后（askDeferSec默认120秒内）且期间你没发新消息、没有正在看你分享的视频，就把这次当作刚才请求的延续交给HDS，由HDS决定发不发；发就卡片在前、原分段在后；新消息即取消。④/bili status版本号从package.json读取，始终显示候选池（含“空”）与待补发。⑤Atri自己分享卡片（要视频、补发、/bili pick、自动选片）且卡片取得回执后，她也会自己点开看：第二台画面+声音（不受framesScope限制；未开启第二台则用文字资料），HDS生成补充感想，随机等待selfWatchWaitMinSec–MaxSec（默认30–120秒）后发出；你问“看了没/怎么样”会提前发。不打断正在看你分享的视频；你新分享视频会替换它。selfWatchEnabled=false关闭。

诊断修复：明确要视频且有候选时默认发出（说“发了”必须带链接）；按插件真实卡片记录纠正“我已经发过”的错觉；HDS同回合重写时保留候选；修正“你最近看的视频”搜索词；新增要视频/候选/卡片全过程日志，`journalctl -u hds-interlude.service | grep atri-bilibili` 可查。

**0.7.7**：要视频时候选读取最多等askWaitSec（默认4秒），超时先由HDS自然回应，后台读好的候选下次直接用；自动选片只用后台已读好的候选（candidatePoolMinutes默认60）；观看任务生成前与投递前都让位HDS正在处理的回合，忙碌时退避等待、不再30秒就丢弃草稿；开场太像不再额外调用模型重写，直接转为不回。

**0.7.6 / 0.5.3**：收到视频后约70%先回一句再去看、30%已读不回直接去看，看完回来自然说“刚看完”。对方明确说“你看看/帮我看看”必定先回；最多连续2次不回、最多连续4次先回。开场不再写死“准备去看看”：每次随机给HDS一个说法方向（一两个字、反问、带条件、调侃、嫌麻烦、按当下状态等）与长度，附最近8条开场要求换说法，太像重写一次、仍像则改为直接去看；可对QQ卡片标题随口反应（不评价内容）；先回时约10%只发一个HDS本地表情包。“等会看”类开场等待放宽（最长10分钟）；不回时读取失败会在几秒内如实说明。眼镜新配置：ackProbability=0.7、ackMaxSkipStreak=2、ackMaxAckStreak=4、ackVariety=true、ackHistorySize=8、ackTitleReaction=true、ackStickerRatio=0.1。旧眼镜0.5.2不传这些配置时保持原来“必定先回”。

**0.7.5**：看视频时同时听声音。第二台atri-senses 0.2.0抽6帧并截取开头音频（默认600秒），按第二台config.json的线路顺序理解：line1 a6api gemini-3.8-flash（Gemini原生接口，画面+声音，经主服务器squid代理<请填写主服务器WireGuard地址>:3128），失败再用line2 DeepSeek（只看画面，注明没有声音）。资料以“视频观看资料：画面/听到/整体”交给HDS。framesWaitSec默认180，建议眼镜taskTimeoutSec调到300。需第二台同时升级到0.2.0。

**0.7.4**：新增配置“04 第二台画面抽帧”（framesEnabled默认关闭、framesUrl默认http://<请填写第二台WireGuard地址>:8101、framesToken、framesScope=shared|all、framesWaitSec默认120）。本人分享视频时，读完API资料后请第二台atri-senses（WireGuard内网）匿名取流、均匀抽6帧、按三条识图线路依次尝试（空回/超时/报错自动切换），结果以“画面抽帧（仅静止画面）”附在资料后交给HDS；同一BV缓存6小时；失败或超时只附“画面抽帧未取得[原因]”，不影响原流程。/bili status显示第二台在线、今日任务与线路冷却。开启后建议把眼镜taskTimeoutSec调到240。

**0.7.3**：新增“要视频”流程（askEnabled，默认开启）。识别“有没有什么好看的视频发我看看”“发个猫猫视频”“推荐个原神视频”等明确请求；读取最多candidateLimit个未看过的候选（有关键词就搜索，否则热门），交给HDS按此刻在做什么、心情、关系与刚才的对话自己决定。发：第一气泡放唯一URL，插件先转成QQ小程序卡片，停顿2–5秒（cardGapMinSec/cardGapMaxSec）后发HDS原分段文字；不发：按人设回应，不放链接、不假装已发。要视频的话不会被当作观看追问吞掉。眼镜仍为0.5.2。

**0.7.2 / 0.5.2**：新增单任务观看状态机、HDS开场确认后读取、内存预回复、随机等待、追问合并、最终发送互斥、超时/取消/任务替换与重启不重放。普通聊天不吞掉；只对已有观看任务的相关短追问或明确视频内容追问合并。草稿的其他记忆、跨会话、媒体、日程动作不执行。

## 安装

将ZIP上传到服务器家目录后执行：

```bash
cd ~
unzip -q Atri_Bili_API_0.7.8_连贯版.zip
cd atri-bili-api-0.7.8
sha256sum -c SHA256SUMS
bash scripts/install-upgrade.sh /opt/hds-interlude hds-interlude.service
```

两插件都升级，保留原实例、会话与HDS数据。旧目录存在时换新目录，不盲目覆盖混包。脚本私有备份原配置、锁文件、依赖及data后离线安装；不改人设或koishi.yml，仅恢复原本活动的服务。备份含隐私，不上传公开仓库；.atri-bili-packages/api-0.7.8是安装源，不随手删除。

## 眼镜配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| autoReadShared | true | 本人私聊分享识别 |
| watchPacing | true | 开启观看节奏；false恢复0.5.1即时读取后回复 |
| waitMinSec | 30 | 预回复就绪后的最短等待秒数 |
| waitMaxSec | 90 | 最长等待秒数；0–600，起止颠倒自动排序 |
| taskTimeoutSec | 180 | 开场生成/确认上限，以及读取+生成草稿合计上限，两段分别计时；30–600秒 |

倒计时从**预回复生成完成**后开始，不代表视频播放进度。主插件仍需配置本人targetUserId、机器人selfId与正常HDS。现有旧false不会自动打开。HDS需rc57兼容接口；接口不满足时不会绕过去生成模板开场或先读后冒充按节奏执行。

## 日常用法

在本人QQ私聊发BV、正式视频链接或转发B站QQ JSON卡片。一次只发一个不同目标；卡片只读明确跳转字段，不根据标题猜视频。管理指令不是SSH命令。

任务进行中，“看完了吗”“怎么样了”“这个视频讲了什么”“这个你看看”等相关消息会合并；预回复未生成时不单独回复。消息仍按用户原话记录到HDS，不伪造新用户发言。完全无关话题正常走HDS，定时分享碰到前台回合会短暂让路，最多30秒，持续忙碌则终止而非无限插话。

同一视频再次发送合并到当前任务，不重复开场；新视频取消旧未完成任务，重新走新开场；“不用看了/别看了/取消观看/停止观看”取消当前任务并回交普通HDS。多目标消息不自动选择其中一个。识别有边界，复杂隐含追问不保证被合并。

| 指令 | 用途 |
| --- | --- |
| /bili status | 主版本、HDS、观看任务状态/剩余等待、暂停和限额 |
| /bili pick [兴趣词或BV] | 原HDS选片分享，非本次入站观看倒计时 |
| /bili read BV号；/bili search 关键词 | 原只读调试/搜索 |
| /bili pause；/bili resume | 暂停并取消待发任务；恢复不重放 |
| /bili history | 原推荐QQ卡片记录，不等于全部观看任务历史 |
| /bili login；/bili login-check | 官方扫码及手动检查，约3分钟有效 |
| /bili cancel-login；/bili logout | 取消扫码/清本地扫码登录；logout取消观看任务 |
| /bili account；/bili session；/bili prepare | 账号核对、脱敏会话、官方设备标识 |

## 失败与安全

- 开场必须得到HDS确认且绑定原输入/剧本；没有回执就不读视频、不自动重发开场。
- 读取失败时让HDS基于失败事实生成一次如实回应；不换视频、不编造内容。HDS本身无法生成时只记录失败，不用固定角色文案代替。
- 草稿不提前写成HDS已发送对话；真正到发送时才通过HDS persistDecision和原生投递记录。最终“sent”仅代表首段取得HDS投递回执，后续分段仍由HDS按原规则管理，不代表用户已读。
- 倒计时和追问争抢同一份草稿，只执行一次。未确认投递不自动重发。两次开场/最终感想发送并非事务。
- 暂停、权限/身份变动、HDS任务代际失效、原输入或开场剧本被删时停止。插件热重载/重启不恢复旧草稿，发送中的任务记unknown，其余未完成任务取消。
- 正在进行的网络/模型调用不一定能被撤回，但超时/取消后的迟到结果不再投递；新任务也可能遇到旧请求尚占用读取槽，届时如实失败，不自动重试。
- 延迟分享是本人视频请求的后续回复，标记为userInitiated交给HDS原生端点/白名单/暂停门控；不修改或打开全局主动消息开关。后台无关选片仍需HDS自己的主动消息许可。
- 私有watch-state-v2.json新增viewTasks元数据，不保存草稿正文；旧账本、会话和data保留。Cookie/Key不进入源码、项目表或公开日志。
