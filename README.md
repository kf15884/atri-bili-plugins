# Atri Bili：HDS观看节奏版

主插件 **0.7.2** + 眼镜 **0.5.2**。本人私聊分享B站链接、BV或B站QQ JSON卡片后，先由HDS回应准备去看，再读实际资料并生成待发送感想，随机等待或在追问时提前分享。

## 功能简介

```text
明确分享一个视频 → HDS按原人设回应“准备去看看”
                        ↓ 取得真实HDS投递确认后
               眼镜读取API文字资料、可用字幕
                        ↓
               HDS生成预回复（仅内存，不提前入库/发送）
                        ↓
               随机等待30–90秒（可配置）
                ├─ 相关追问 → 提前发出预回复
                └─ 无追问 → 到时按HDS原链路发送
```

预回复未就绪时的相关追问静默合并；生成完成后立即发，不再等待。所有角色文字都由HDS生成，保持原人设、关系、记忆、分段和消息门控，不用插件独立模型/固定模板。分享视频默认只聊感想、不重复回卡。原`/bili pick`和HDS生活推进选片仍为卡片在前、原格式感想在后。

**资料读取不等于真实音视频播放。** 仅取得元信息、可用字幕与可选弹幕；没有画面/音频输入，不假称完整看完。不执行站内评论、艾特、回复、点赞等写入，无Puppeteer依赖。

## 最新更新

**0.7.2 / 0.5.2**：新增单任务观看状态机、HDS开场确认后读取、内存预回复、随机等待、追问合并、最终发送互斥、超时/取消/任务替换与重启不重放。普通聊天不吞掉；只对已有观看任务的相关短追问或明确视频内容追问合并。草稿的其他记忆、跨会话、媒体、日程动作不执行。

## 安装

将ZIP上传到服务器家目录后执行：

```bash
cd ~
unzip -q Atri_Bili_API_0.7.2_HDS观看节奏版.zip
cd atri-bili-api-0.7.2
sha256sum -c SHA256SUMS
bash scripts/install-upgrade.sh /opt/hds-interlude hds-interlude.service
```

两插件都升级，保留原实例、会话与HDS数据。旧目录存在时换新目录，不盲目覆盖混包。脚本私有备份原配置、锁文件、依赖及data后离线安装；不改人设或koishi.yml，仅恢复原本活动的服务。备份含隐私，不上传公开仓库；.atri-bili-packages/api-0.7.2是安装源，不随手删除。

## 眼镜配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| autoReadShared | true | 本人私聊分享识别 |
| watchPacing | true | 开启观看节奏；false恢复0.5.1即时读取后回复 |
| waitMinSec | 30 | 预回复就绪后的最短等待秒数 |
| waitMaxSec | 90 | 最长等待秒数；0–600，起止颠倒自动排序 |
| taskTimeoutSec | 180 | 开场生成/确认上限，以及读取+生成草稿合计上限，两段分别计时；30–600秒 |

倒计时从**预回复生成完成**后开始，不代表视频播放进度。主插件仍需配置本人targetUserId、机器人selfId与正常HDS。现有旧false不会自动打开。HDS需rc57兼容接口；接口不满足时不会绕过去生成模板开场或先读后冒充按节奏执行。

## 日常用法

在本人QQ私聊发BV、正式视频链接或转发B站QQ JSON卡片。一次只发一个不同目标；卡片只读明确跳转字段，不根据标题猜视频。管理指令不是SSH命令。

任务进行中，“看完了吗”“怎么样了”“这个视频讲了什么”“这个你看看”等相关消息会合并；预回复未生成时不单独回复。消息仍按用户原话记录到HDS，不伪造新用户发言。完全无关话题正常走HDS，定时分享碰到前台回合会短暂让路，最多30秒，持续忙碌则终止而非无限插话。

同一视频再次发送合并到当前任务，不重复开场；新视频取消旧未完成任务，重新走新开场；“不用看了/别看了/取消观看/停止观看”取消当前任务并回交普通HDS。多目标消息不自动选择其中一个。识别有边界，复杂隐含追问不保证被合并。

| 指令 | 用途 |
| --- | --- |
| /bili status | 主版本、HDS、观看任务状态/剩余等待、暂停和限额 |
| /bili pick [兴趣词或BV] | 原HDS选片分享，非本次入站观看倒计时 |
| /bili read BV号；/bili search 关键词 | 原只读调试/搜索 |
| /bili pause；/bili resume | 暂停并取消待发任务；恢复不重放 |
| /bili history | 原推荐QQ卡片记录，不等于全部观看任务历史 |
| /bili login；/bili login-check | 官方扫码及手动检查，约3分钟有效 |
| /bili cancel-login；/bili logout | 取消扫码/清本地扫码登录；logout取消观看任务 |
| /bili account；/bili session；/bili prepare | 账号核对、脱敏会话、官方设备标识 |

## 失败与安全

- 开场必须得到HDS确认且绑定原输入/剧本；没有回执就不读视频、不自动重发开场。
- 读取失败时让HDS基于失败事实生成一次如实回应；不换视频、不编造内容。HDS本身无法生成时只记录失败，不用固定角色文案代替。
- 草稿不提前写成HDS已发送对话；真正到发送时才通过HDS persistDecision和原生投递记录。最终“sent”仅代表首段取得HDS投递回执，后续分段仍由HDS按原规则管理，不代表用户已读。
- 倒计时和追问争抢同一份草稿，只执行一次。未确认投递不自动重发。两次开场/最终感想发送并非事务。
- 暂停、权限/身份变动、HDS任务代际失效、原输入或开场剧本被删时停止。插件热重载/重启不恢复旧草稿，发送中的任务记unknown，其余未完成任务取消。
- 正在进行的网络/模型调用不一定能被撤回，但超时/取消后的迟到结果不再投递；新任务也可能遇到旧请求尚占用读取槽，届时如实失败，不自动重试。
- 延迟分享是本人视频请求的后续回复，标记为userInitiated交给HDS原生端点/白名单/暂停门控；不修改或打开全局主动消息开关。后台无关选片仍需HDS自己的主动消息许可。
- 私有watch-state-v2.json新增viewTasks元数据，不保存草稿正文；旧账本、会话和data保留。Cookie/Key不进入源码、项目表或公开日志。
